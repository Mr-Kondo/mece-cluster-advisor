# 次元削減の評価

埋め込みを KMeans にかける前に、次元削減(PCA・UMAP・PaCMAP・t-SNE)を挟むと、日本語の話題のグルーピングは良くなるかを測った。結論は「今は入れない」である。t-SNE は、v0.4.0 の後に追加で測った([Issue #21](https://github.com/Mr-Kondo/mece-cluster-advisor/issues/21))。その後、t-SNE の調整と乱数([#28](https://github.com/Mr-Kondo/mece-cluster-advisor/issues/28))と、件数・モデル・口語の短文への拡張([#29](https://github.com/Mr-Kondo/mece-cluster-advisor/issues/29))を測った。

## 結論

- UMAP は、生の埋め込みよりわずかに良い。ARI で約 +0.02、NMI で約 +0.024 で、20 組中 18〜20 組で上回った。
- PaCMAP と PCA は、生の埋め込みと差が見分けられなかった。PCA の白色化は、大きく悪化した(ARI が約 −0.19)。
- t-SNE は、2 次元(perplexity 30)で差が見分けられなかった(ARI で −0.001)。向きも設定で割れた(`title` で下がり、`lead` で上がった)。3 次元と perplexity 15 では、悪化した(ARI で −0.05、−0.04)。UMAP を上回る条件は、見つからなかった。
- 差が小さいことに加え、UMAP と PaCMAP は依存が重く、このスキルの構成では macOS で落ちた。見合わないので、入れない。

- 追加の評価(下の「追加の評価」)でも、既定のモデル(ruri-v3-310m)では、次元削減の利得は ARI で +0.03 以下だった(UMAP。口語の短文では t-SNE が +0.049)。別のモデル(multilingual-e5-small)では、UMAP が +0.054〜+0.090 になり、「入れ直す条件」(ARI で 0.05 以上)を満たした。ただし、このスキルの既定ではない。

現状(次元削減なしで、生の埋め込みを KMeans にかける)を維持する。

## 問い

現状の `scripts/mece_cluster.py` は、768 次元の正規化済み埋め込みを、そのまま KMeans にかけている。silhouette は元の cosine 距離で測る。次元削減を挟むと、グループが正解のカテゴリに近づくかを調べた。

| PCA 64 次元(白色化) | 0.242 ± 0.047 | 0.356 ± 0.046 | 0.314 ± 0.040 | 0.434 ± 0.037 |
| UMAP 10 次元 | 0.455 ± 0.011 | 0.558 ± 0.008 | 0.515 ± 0.009 | 0.608 ± 0.009 |
| PaCMAP 10 次元 | 0.449 ± 0.014 | 0.550 ± 0.018 | 0.490 ± 0.016 | 0.586 ± 0.014 |
| t-SNE 2 次元 | 0.414 ± 0.018 | 0.508 ± 0.013 | 0.512 ± 0.023 | 0.593 ± 0.016 |

### HDBSCAN(UMAP 10 次元の出力に適用)

ノイズ(どのグループにも入らない項目)が約 2 割で、グループが 16〜19 個に割れた(正解は 9)。生の埋め込みに直接かけると、8〜9 割がノイズになった。MECE は全項目をどこかに入れる分割なので、合わない。

900 件で、UMAP は 1 回あたり約 1 秒、PaCMAP は約 0.3 秒、t-SNE は 2 次元で約 0.9 秒、3 次元で約 1.6 秒、PCA は計算時間が無視できる程度だった。UMAP は初回に numba の準備で数秒かかる。t-SNE は件数が増えると遅くなる。大きな件数では測っていない。

- 既定のモデル(ruri-v3-310m)では、UMAP は全条件で正だが +0.03 以下だった。件数を 4 倍にしても、利得は +0.02 前後で、大きくならなかった。
- 件数が増えると、PaCMAP(−0.08〜−0.10)と t-SNE(−0.02〜−0.04)は悪化した。ニュース記事の話題では、UMAP だけが正を保った。
- 口語の短文(MASSIVE ja)では、PCA を除く手法が正に寄った。t-SNE は +0.049 で、ニュース記事の結果と向きが逆である。
- 軽量な ruri-v3-30m では、ほぼ差が無かった。

## t-SNE の調整と乱数(#28)

`evals/dr_extend.py tsne` で、livedoor の 900 件(2 設定 × 2 サンプル × 5 シード = 20 組)に、t-SNE の変種を当てた。ARI(k=9)の、生の埋め込みとの差である。

| 変種 | 差(平均 ± 標準誤差) | 上回った組 |
|---|---|---|
| scikit-learn、perplexity 30(基準) | −0.001 ± 0.007 | 10/20 |
| perplexity 5 / 10 / 100 | −0.087 / −0.048 / +0.001 | 0 / 2 / 9 |
| 初期値 `random` | +0.007 ± 0.007 | 10/20 |
| 学習率 50 / 1000 | −0.003 / −0.013 | 9 / 7 |
| 反復 250 / 3000 | −0.148 / −0.002 | 0 / 10 |
| early exaggeration 4 / 24 | −0.006 / −0.015 | 6 / 5 |
| openTSNE、perplexity 30 / 100 | −0.015 / +0.001 | 6 / 12 |
| openTSNE、初期値 `random` | −0.006 | 7/20 |

- どの変種も、生の埋め込みを有意に上回らなかった(最大でも +0.007 ± 0.007)。perplexity が小さい、反復が少ない設定は、はっきり悪化した(収束していない)。openTSNE も、scikit-learn と同じ水準だった。
- 乱数の切り分け: 基準の t-SNE で、t-SNE の乱数 5 通り × KMeans の乱数 5 通りの格子を取った。KMeans の乱数で平均した ARI の、t-SNE の乱数による標準偏差は 0.009〜0.024(セルごと)で、t-SNE の乱数が、ばらつきの主な原因だった。同じ t-SNE の出力に対する KMeans の乱数のばらつきは 0.001〜0.005 で、生の埋め込みに KMeans をかけたときの 0.004〜0.023 より小さかった。
- 乱数の影響(約 ±0.02)は、基準との差(約 0.01)より大きい。v0.4.1 で「−0.001」とした値は、差が無いことを示す。

## 入れない理由

1. **差が小さい。** UMAP の利得は ARI で約 0.02 で、手法やシードによる ARI の標準偏差(約 0.01〜0.02)と同じ大きさである。PaCMAP と PCA は差が見分けられない。
2. **依存が重い。** UMAP は numba と llvmlite(約 39MiB)、PaCMAP は numba と faiss を連れてくる。このスキルは、初回に数百 MB を取得するのを許容してもらっているが、効果が小さいものに足す重さではない。
3. **macOS で落ちた。** UMAP / PaCMAP と torch を同じプロセスに読み込むと、SIGSEGV(終了コード 139)で落ちた。このスキルは、埋め込み(torch)とクラスタリングを 1 つのプロセスで行う。次元削減を足すには、プロセスを分ける設計変更が要る。
4. **距離が歪む。** UMAP の出力は、元の cosine 距離を保たない。silhouette を元の空間で測ると、UMAP の分割は低くなった(`title` で 0.062、生の埋め込みは 0.070)。t-SNE も同じで、`title` で 0.057(2 次元)だった。
5. **t-SNE は、効果が見えず、使いにくい。** 依存は増えない(scikit-learn にある)ので、重さは理由にならない。だが 2 次元で差が見分けられず、3 次元と perplexity 15 では悪化した。perplexity で結果が動く。`TSNE` には `transform` が無く(実行して確認した)、新しい項目を後から加えるには、全件を計算し直す必要がある。このスキルは 1 回の実行で全件を処理するので、この点は致命的ではないが、利点にもならない。

## 読むときの注意

- 標準誤差は、20 組(2 設定 × 2 サンプル × 5 シード)を独立とみなして計算した値である。同じサンプルを共有する組は独立でなく、サンプルも 2 つしかないので、実際の不確かさより小さく見える。推測統計の結論ではなく、目安として読む。設定・サンプル別の差は、全組で同じ向きかを見るために載せた(下の表)。
- 上の主な表は、1 つのコーパス(整った文章のニュース)、1 つの埋め込みモデル(ruri-v3-310m)、900 件での結果である。口語の短文、3,789 件、別のモデル 2 つは、「追加の評価」で測った。数千件を超える件数や、ほかのコーパス(話題の粒度が違うもの)は測っていない。
- 正解は記事のカテゴリで、MECE の正解ではない。カテゴリには近い話題が混ざる。
- t-SNE の調整(openTSNE、初期値、学習率、反復回数、perplexity 5〜100)は、上の「t-SNE の調整と乱数」で測った。いずれも livedoor の 900 件での結果である。
- t-SNE の乱数によるばらつきは、「t-SNE の調整と乱数」で切り分けた(t-SNE の乱数が主因で、約 ±0.02)。主な表の標準偏差は、2 サンプルをまとめた値で、サンプルの違いを含む。
- TriMap は評価していない。文献では、TriMap は局所構造に弱く結果が安定しないとされる。
- 「入れない」は、この条件での判断である。

## 入れ直す条件

次のどれかが確かめられたときに、改めて検討する。

- 数千件以上、または別のモデルで、UMAP の利得が大きく(目安として ARI で 0.05 以上)なる。
- 埋め込みとクラスタリングを別プロセスにする構成に、別の理由で変える。

入れるときは、opt-in の `--reduce` にし、silhouette は元の cosine 距離で測り続ける。

1 つ目の条件(別のモデルで ARI 0.05 以上)は、multilingual-e5-small で満たされた。満たされたことを受けて、入れるかどうかを [Issue #39](https://github.com/Mr-Kondo/mece-cluster-advisor/issues/39) で検討する。

## 副次的な観察: 自動で選ぶ k

生の埋め込み・PCA・UMAP では、silhouette が最大の k として選ばれた k は平均で約 4 だった(正解は 9)。PaCMAP は 2〜4、t-SNE は `title` で 2.6〜3.0、`lead` で約 4、白色化した PCA は約 8 だった。生の埋め込み・PCA・UMAP で選ばれた k での ARI は 0.33〜0.36 で、k=9 のときより 0.1 以上低い。次元削減では直らない。この点は [Issue #17](https://github.com/Mr-Kondo/mece-cluster-advisor/issues/17) で扱う。

## 再現

```bash
uv run evals/dr_extend.py scale --dataset massive                         # 口語の短文
uv run evals/dr_extend.py scale --dataset livedoor --per-class 500        # 件数を増やす
uv run evals/dr_extend.py scale --model intfloat/multilingual-e5-small    # 別のモデル
uv run evals/dr_extend.py tsne                                            # t-SNE の調整と乱数
uv run evals/dr_bench.py                                          # 全設定(数分)
uv run evals/dr_bench.py --settings title --subs 0 --seeds 0      # 動作確認(短い)
```
