## 変更

- `--device auto` で選んだアクセラレータ(MPS・XPU・DirectML・NPU・HPU など、CUDA 以外も含む)で読み込みや計算が失敗したとき、標準エラーに理由を出して CPU でやり直す。結果の `meta.device` は、実際に使った `cpu` になる。ネットワークやファイルの失敗(`OSError`)は、CPU に替えても直らないので、やり直さない。`--device` を明示したときは、今までどおり失敗する(#37)。
- auto が CPU に落ちたとき、`nvidia-smi`・`rocm-smi` がある環境、または Windows では、GPU を使えていない可能性と直し方(GPU 対応の torch、`torch-directml`)を標準エラーに出す。GPU の有無そのものは判定していないので、文面は条件つきである(#37)。

選ぶ順(cuda → mps → xpu → DirectML → npu → hpu → `torch.accelerator` → cpu)は変えていない。

## 確認したこと

- この Mac で、`--device auto`(mps)と `--device cpu` の分け方と silhouette(0.0778)が一致した。`--device cuda` は `error: デバイス 'cuda' は利用できません…` で止まる。
- フォールバック(auto は CPU に戻り、明示は失敗のまま、`OSError` は戻らない)とヒントの出し分けを、torch とモデルを差し替えた単体テストで確かめた。CI で走る。

## 確かめていないこと

- MPS・XPU・DirectML・NPU・HPU が実際に失敗した場面でのフォールバック。実機で失敗を起こしていない(差し替えだけ)。
- CUDA・Intel XPU・DirectML・NPU の実機での実行(#26)。
