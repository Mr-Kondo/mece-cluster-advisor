## 重要: インストール先に、実行環境の設定が複製されていないか確認してください

v0.3.1 以前の `install.py` は、リポジトリ直下に `.codex/`・`.serena/`・`.venv/`・`feedback/` があると、インストール先(`~/.claude/skills/mece-cluster-advisor`、`~/.agents/skills/mece-cluster-advisor`)へそのまま複製していました。`.codex/config.toml` などにはトークンが入っていることがあります。v0.4.0 で、この 4 つを除外しました(#14)。

- 手元のリポジトリから v0.3.1 以前の `install.py` を実行したことがあれば、上の 2 か所に `.codex`・`.serena`・`.venv`・`feedback` が無いか確認してください。あれば削除し、そこに入っていたトークンは無効にして再発行してください。
- この Release の zip から入れる場合は、影響を受けません(追跡されているファイルだけが入ります)。

## 追加

- **版の確認。** リポジトリ直下に `VERSION` を置いた。`scripts/skill_info.py --version` と `scripts/mece_cluster.py --version` が「mece-cluster-advisor 版」を出す(#11)。
- **実行環境の記録。** `scripts/skill_info.py --model <モデル名>` が、版・OS・アプリ・モデル・日付を JSON で出す。標準ライブラリだけで動き、ファイルを書き込まず、ユーザー名・ホスト名・パスを出さない。保存先 `~/.agents/skill-env/mece-cluster-advisor.json` は標準エラーの `save_to` に示す(#11)。
- **リリースの自動化。** `main` の `VERSION` が変わると、GitHub Actions がタグ `v<版>`・zip・sha256・Release を作る(#11)。この v0.4.0 が、その最初のリリースである。
- **自動で選ぶ k の注意。** `--k auto` で k を選んだとき、`meta.warnings` に「実際の話題の数より小さい k を選びやすい。目的から k が決まるなら `--k` で指定する」を常に出す。9 カテゴリのデータで、選ばれた k は平均約 4 だった(#17)。

## 修正

- `install.py` が `.codex/`・`.serena/`・`.venv/`・`feedback/` をコピーしないようにした。CI に、コピーされないことの検査を足した(#14)。
- 検証用の出力フォルダ `feedback/` を `.gitignore` に追加した(#10)。

## 変更

- 依存の下限を更新した(#9): sentence-transformers 6.2.0、transformers 5.22.0、torch 2.15.0、sudachidict-core 20261015。

## 評価の記録(動作は変わらない)

- [次元削減の評価](https://github.com/Mr-Kondo/mece-cluster-advisor/blob/v0.4.0/docs/dimensionality-reduction.md)(#12): PCA・UMAP・PaCMAP を、livedoor ニュース 900 件で比べた。UMAP は ARI で約 +0.02 とわずかに良いが、依存が重く、torch と同じプロセスで macOS では落ちたため、入れない。再現は `evals/dr_bench.py`。
- [自動で選ぶ k の評価](https://github.com/Mr-Kondo/mece-cluster-advisor/blob/v0.4.0/docs/k-selection.md)(#17): k の選び方を 5 通り比べ、話題の数に安定して追従するものはなかった。選び方は変えない。再現は `evals/k_selection_bench.py`。

## 確認したこと

- 単体テスト(`scripts/test_mece_cluster.py`、`scripts/test_skill_info.py`)と、`install.py` のインストール・アンインストール・`--purge` の検査を、GitHub Actions の Linux と Windows で通した。
- 新しい依存の下限で、実モデル(ruri-v3-310m)を使った実行を、macOS(Apple Silicon)の CPU で確かめた(17 件を 3 グループに分割)。

## 確かめていないこと

- Linux・Windows での実モデルの実行(CI は、モデルを使わない検査まで)。
- CPU 以外のデバイス(CUDA・MPS・Intel XPU・DirectML・NPU)での実モデルの実行。この版で確かめた実行は CPU だけである。デバイスを選ぶ処理は v0.3.0 から変更していない。
