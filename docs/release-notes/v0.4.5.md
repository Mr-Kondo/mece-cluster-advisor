## 検証した結果

- **k の選び方(#30)**: 口語の短文(MASSIVE ja)で、現行の silhouette は m が小さいと大きく選び(m=3 で 5.8)、m が 9 以上ではおおむね追従した。許容幅つきの基準は、ここでは悪化した(ARI 0.680 → 0.623 と 0.559)。許容幅を採らない判断が補強された。[docs/k-selection.md](docs/k-selection.md)
- **次元削減(#28、#29)**: 既定のモデルでは、UMAP の利得は ARI で +0.03 以下だった(3,789 件でも同じ)。件数が増えると PaCMAP と t-SNE は悪化した。口語の短文では t-SNE が +0.049。別のモデル(multilingual-e5-small)では UMAP が +0.054〜+0.090 で、「入れ直す条件」を満たした。入れるかどうかは #39 で決める。t-SNE は、perplexity・初期値・学習率・反復回数・openTSNE のどれでも、生の埋め込みを有意に上回らなかった。t-SNE の乱数による ARI のばらつきは約 ±0.02。[docs/dimensionality-reduction.md](docs/dimensionality-reduction.md)
- **動作環境(#25、#26)**: 実モデルの 17 件で、Linux と Windows(GitHub Actions)と macOS の CPU・MPS の分け方と silhouette(0.0778)が一致した。CUDA・Intel XPU・DirectML・NPU は、実機が無く未確認。確かめ方を [docs/usage.md](docs/usage.md) に書いた。
- **Codex(#31)**: スキル一覧の description は、スキルが多い環境で前方の十数文字に切られる。発動評価は肯定 10/12、否定 0/12 の誤発動だった。description の見直しは #36 で扱う。
- **モデルの選び方(#32)**: 3 モデル × 3 場面 × 3 回の小さな比較では、軽量なモデルも仕込んだ重なりと抜けを見つけ、推論力の高いモデルの優位は出なかった。誤検出はモデルの大きさと並ばず、採点役の判定も採点のたびに変わった。難しい場面は未検証。`SKILL.md` の記述を改めた。[docs/model-choice.md](docs/model-choice.md)
