# 自動で選ぶ k の評価

`--k auto`(既定)は、silhouette 平均が最大の k を選ぶ。この選び方が、実際の話題の数に追従するかを測った。結論は「追従しない。選び方は変えず、データによってずれることを警告で知らせる」である。ずれる向きは、ニュース記事では小さく、短い口語の発話では大きかった([Issue #30](https://github.com/Mr-Kondo/mece-cluster-advisor/issues/30))。

## 結論

- silhouette で選んだ k は、実際の話題の数が増えても、2.5〜4 のあたりにとどまった。9 カテゴリのデータで、平均は約 4 だった。
- 別の基準(Calinski-Harabasz、Davies-Bouldin、silhouette の許容幅つき)も試したが、話題の数に安定して追従するものはなかった。
- 別のコーパス(短い口語の発話、18 分類)では、silhouette の k は小さくならず、m が小さいと大きかった(m=3 で 5.8、m=6 で 8.4)。許容幅つきの基準は、そこでさらに大きくなり、ARI が下がった。許容幅は livedoor で後から選んだ値で、別のコーパスでは通用しなかった。
- 選び方は変えない。自動で k を選んだときの警告(`meta.warnings`)と `SKILL.md` に、「実際の話題の数からずれやすい(ニュース記事では小さく、口語の発話では大きかった)。目的から k が決まるなら `--k` で指定し直す」と書いた。

## 手順

| 項目 | 内容 |
|---|---|
| データ | [次元削減の評価](dimensionality-reduction.md)と同じ livedoor ニュース(CC BY-ND 2.1 JP。評価にだけ使い、再配布しない)。埋め込みも共有する |
| 正解の話題数 m | 9 カテゴリから m = 3・5・7・9 個を選んだ部分集合(カテゴリごとに 100 件)。m < 9 では、4 通りの選び方を使う。m = 9 は選び方が1通りなので、同じ条件が 4 回並ぶ |
| 設定 | `title`(タイトルだけ)と `lead`(タイトルと本文の先頭 150 字) |
| 繰り返し | 2 サンプル × 4 部分集合 × 2 シード = 16 回(1 つの設定・m につき) |
| 手法 | 生の埋め込みを KMeans(`n_init=10`)にかけ、k = 2〜12 を試す。本番の既定の探索範囲(2〜8)より広い |
| 基準 | silhouette 最大(現行)/ Calinski-Harabasz 最大 / Davies-Bouldin 最小 / silhouette が最大から 0.01 以内で最大の k / 同 0.02 以内で最大の k |
| 指標 | 選ばれた k の平均、正解 m との差の絶対値の平均、その k での ARI の平均 |

実行日は 2026-10-30。版は [次元削減の評価](dimensionality-reduction.md)と同じ。

## 結果

## 読み方

- 現行の silhouette は、m=3 では近い k を選ぶが(`lead` で 3.3)、m が 5 以上になると 2.5〜4 にとどまる。ARI が最大になる k は、m とほぼ同じ値で増える(3.4 → 5.4 → 7.2 → 8.8)。
- Calinski-Harabasz は、常に k=2 を選んだ。この埋め込みでは判断材料にならない。
- Davies-Bouldin は、m=3 で 6.6(過大)、m=5 で 2.4(過小)と、向きが一定しない。
- 「最大から 0.02 以内で最大の k」は、平均の ARI が上がる(`title` で 0.393 → 0.457、`lead` で 0.480 → 0.510)。ただし、m=3 では 5.9 と過大に、m=5 では 3.2 と過小になり、m に対して単調でない。0.01 と 0.02 は、結果を見たうえで選んだ幅で、1 つのコーパスでしか確かめていない。

## 変えない理由

1. 話題の数に安定して追従する基準が、見つからなかった。
2. 許容幅つきの基準は、平均では良くなるが、1 つのコーパスで後から調整したもので、m が小さいときに過大になる。別のデータで同じ幅が通用する根拠がない。
3. このスキルの使い方では、k は目的で決まることが多い(施策の優先順位づけなら、扱える数など)。自動の選択は、目安である。

## 別のコーパス: 短い口語の発話(MASSIVE ja)

JMTEB の `massive_scenario_classification`(MASSIVE の日本語。CC BY 4.0。「金曜日の午前九時に起こしてください」のような発話と、18 のシナリオ)で、同じ測り方を繰り返した。

| 項目 | 内容 |
|---|---|
| 項目 | シナリオごとに 100 件、計 1,800 件(サンプルは 2 つ)。埋め込みは `cl-nagoya/ruri-v3-310m` |
| 正解の話題数 m | 18 シナリオから m = 3・6・9・12・18 個を選んだ部分集合(m < 18 では 4 通り) |
| 繰り返し | 2 サンプル × 4 部分集合 × 2 シード。探索範囲は 2〜(m の最大 + 3) |

選ばれた k の平均 / 正解との差の絶対値の平均 / その k での ARI の平均である。

| 基準 | m=3 | m=6 | m=9 | m=12 | m=18 | 差の絶対値(全体) | ARI(全体) |
|---|---|---|---|---|---|---|---|
| silhouette 最大(現行) | 5.8 / 3.1 / 0.64 | 8.4 / 2.9 / 0.69 | 10.1 / 1.2 / 0.77 | 12.9 / 1.8 / 0.67 | 19.5 / 1.5 / 0.63 | 2.10 | 0.680 |
| Calinski-Harabasz | 2.0 / 1.0 / 0.47 | 2.0 / 4.0 / 0.22 | 2.1 / 6.9 / 0.14 | 2.0 / 10.0 / 0.10 | 2.0 / 16.0 / 0.06 | 7.58 | 0.197 |
| Davies-Bouldin | 13.7 / 10.7 / 0.42 | 13.6 / 8.8 / 0.44 | 9.2 / 4.9 / 0.49 | 15.1 / 4.7 / 0.60 | 20.5 / 2.5 / 0.62 | 6.31 | 0.515 |
| silhouette 最大−0.01 以内で最大の k | 8.8 / 5.8 / 0.52 | 11.4 / 5.4 / 0.63 | 12.8 / 3.8 / 0.71 | 17.9 / 5.9 / 0.64 | 21.0 / 3.0 / 0.62 | 4.78 | 0.623 |
| silhouette 最大−0.02 以内で最大の k | 12.2 / 9.2 / 0.39 | 14.8 / 8.8 / 0.54 | 15.7 / 6.7 / 0.66 | 20.3 / 8.3 / 0.59 | 21.0 / 3.0 / 0.62 | 7.21 | 0.559 |
| (参考)ARI が最大になる k | 3.6 | 6.2 | 9.2 | 12.4 | 18.5 | | |

- 現行の silhouette は、m が 9 以上ではおおむね追従した(差は 1〜2)。m が小さいと大きく選んだ(m=3 で 5.8)。livedoor とは逆の向きである。
- 許容幅つきの基準は、ここでは悪化した(差の絶対値 2.10 → 4.78・7.21、ARI 0.680 → 0.623・0.559)。livedoor で平均の ARI を上げた幅が、別のコーパスでは通用しなかった。
- Calinski-Harabasz は、ここでも k=2 に張りついた。Davies-Bouldin は、向きが一定しなかった。

## 対応

- 自動で k を選んだとき、`meta.warnings` に「k は silhouette で自動選択した。実際の話題の数からずれやすい(ニュース記事では小さく、口語の発話では大きかった)。目的から k が決まるなら、`--k` で指定して再実行する」を出す。
- `SKILL.md` の「読み違えやすい点」と、`references/output-schema.md` の `warnings` の説明に、同じことを書いた。

## 注意

- 2 つのコーパス(整ったニュース文章と、短い口語の発話)、1 つの埋め込みモデル(ruri-v3-310m)、クラスごとに 100 件の結果である。別のモデルでは測っていない。
- カテゴリは MECE の正解ではない。近い話題が混ざるので、「正しい k」は 9 とは限らない。

## 再現

```bash
uv run evals/k_selection_bench.py                                   # livedoor
uv run evals/k_selection_bench.py --dataset massive --ms 3 6 9 12 18  # 口語の発話
```

データと埋め込みのキャッシュは、[次元削減の評価](dimensionality-reduction.md)と共有する(`feedback/dr-bench/`、Git の対象外)。
