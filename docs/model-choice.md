# モデルの選び方の評価

`SKILL.md` の「モデルの選び方」には、「グループの命名は軽量なモデルでも足りる。排他性の判定と網羅性の指摘は、推論力の高いモデルのほうが向く」という目安がある。この目安を、小さな比較で確かめた([Issue #32](https://github.com/Mr-Kondo/mece-cluster-advisor/issues/32))。結論は「この比較では、モデルの大きさによる差は出なかった。目安は支持も否定もできない」である。

## 手順

| 項目 | 内容 |
|---|---|
| モデル | `claude-haiku-5-5`(軽量)、`claude-sonnet-5-5`、`claude-opus-5-5`(推論力が高い)。Claude Code の `claude -p`(設定・フック・ツールは読み込まない) |
| 入力 | 場面ごとに、項目(`evals/model-choice/*.txt`)、道具(`scripts/mece_cluster.py`)の出力、目的、利用者の分類案 |
| 課題 | グループの命名 / 排他性(重なるカテゴリの組と根拠)/ 網羅性(抜けている観点)/ 結論(使ってよいか) |
| 場面 `overlap` | 分類案に、重なる 2 カテゴリ(画面の操作性 / 使い方の分かりにくさ)を仕込んだ(32 件) |
| 場面 `gap` | 目的が求める観点のうち、職場の人間関係の項目が 1 件も無い(24 件) |
| 場面 `clean` | 分類案は目的に合っている。重なりや抜けを構造的な問題として指摘したら誤検出(24 件) |
| 繰り返し | 3 モデル × 3 場面 × 3 回 = 27 回答 |
| 採点 | 固定の採点役(`claude-sonnet-5-5`)が、仕込んだ事実に対する是非の問いに答える。回答の全文は `feedback/model-choice/` に保存。保存した回答の採点し直しは `--regrade` |
| 実行日 | 2026-10-30 |

## 結果

同じ 27 回答を、採点役に 2 回採点させた。1 回目は回答と問いだけ、2 回目は道具の出力(グループの代表項目とキーワード)も渡した(命名の根拠が無いという指摘を受けたため)。表は 2 回目の値で、括弧内は 1 回目の値である。

各セルは 3 回のうちの該当回数である。「指摘」は、仕込んだ問題(`overlap` は重なり、`gap` は抜け)を指摘した回数。`clean` では、構造的な問題として指摘した回数で、誤検出の意味になる。「誤検出」は、仕込んでいない組の重なりを構造的な問題として指摘した回数(`clean` では、結論を「使えない」とした回数)。命名は、グループの名前案が内容に合っているかの 0〜3 点の平均。秒は回答にかかった時間(1 回目の実行)。

| 場面 | モデル | 指摘 | 誤検出 | 命名 | 秒 |
|---|---|---|---|---|---|
| overlap | haiku | 3/3 (3/3) | 0/3 (1/3) | 3.0 (3.0) | 43 |
| overlap | sonnet | 3/3 (3/3) | 1/3 (3/3) | 2.7 (3.0) | 18 |
| overlap | opus | 3/3 (3/3) | 0/3 (1/3) | 3.0 (2.7) | 44 |
| gap | haiku | 3/3 (3/3) | 3/3 (1/3) | 3.0 (3.0) | 30 |
| gap | sonnet | 3/3 (3/3) | 1/3 (1/3) | 3.0 (3.0) | 17 |
| gap | opus | 3/3 (3/3) | 2/3 (3/3) | 3.0 (3.0) | 29 |
| clean | haiku | 2/3 (1/3) | 0/3 (0/3) | 2.0 (2.3) | 33 |
| clean | sonnet | 3/3 (3/3) | 3/3 (2/3) | 2.7 (2.0) | 18 |
| clean | opus | 0/3 (1/3) | 0/3 (0/3) | 2.0 (2.0) | 39 |

- 仕込んだ重なりと抜けは、軽量なモデルも 3 回とも指摘した(2 回の採点で同じ)。推論力の高いモデルの優位は出なかった。
- 誤検出と `clean` の指摘は、同じ回答でも、採点のたびに変わった(例: `gap` の haiku の誤検出が 1/3 から 3/3)。モデルの大きさとの関係は読み取れない。`clean` で sonnet が 2 回とも多く指摘した点だけは、2 回の採点で一致した。
- 命名は、どのモデルも 2.0〜3.0 で、差は小さい。

## 読むときの注意

- 仕込んだ問題が分かりやすかった。3 モデルとも満点で、差を測る余地が無かった(天井効果)。差が出るのは、もっと微妙な重なりや、目的の読み取りが要る抜けかもしれない。
- 1 場面 3 回ずつで、誤検出の差は偶然の範囲である。
- 採点役も LLM で、採点が安定しない。上のとおり、同じ回答の誤検出の判定が、採点のたびに変わった。仕込んだ問題の指摘(3/3)だけが安定していた。採点役と同じ系統の `sonnet` が有利に採点された可能性もある。回答の全文は残してあるので、読み直せる。
- Claude のモデルだけを測った。Codex など、ほかのホストモデルでは測っていない。
- 「clean」の分類案は、完全に MECE ではない(返品の案内は、問い合わせ対応にも商品情報にも読める)。指摘が必ず誤りとは言えない。

## 再現

```bash
uv run evals/model-choice/run.py                                  # 3 モデル × 3 場面 × 3 回
uv run evals/model-choice/run.py --repeats 1 --models claude-haiku-5-5 --scenarios overlap   # 動作確認
```

呼び出しは利用者の Claude Code の契約を使う。結果は `feedback/model-choice/`(Git の対象外)に置く。
