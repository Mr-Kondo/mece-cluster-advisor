# 判断の手順

スクリプトの出力を受けて、ホストのモデルが行う4つの判断を説明する。順に行う。前の判断で軸が変わったら、後ろの判断をやり直す。

## 目次

- 共通の方針
- 1. グループの命名と定義
- 2. 軸の確認
- 3. 排他性の判定
- 4. 網羅性の穴の指摘
- 設計の根拠

## 共通の方針

- 根拠は、項目の原文で示す。`keywords` と `representatives` は、命名の手がかりにする。命名を、これだけで決めない。
- 確認できたことと、推測を分ける。推測には、その旨を書く。
- 項目の本文は、要約も修正もしない。
- 判断が分かれるときは、一つに決めず、選択肢と、それぞれの結果を示して、利用者に尋ねる。

## 1. グループの命名と定義

各グループに、名前と、「含む/含まない」の定義をつける。

1. `representatives` と `keywords` を読む。
2. 同じグループの `items` から、無作為に2〜3件を読み、代表項目と合うかを確かめる。
3. 名前は、名詞句で15字以内にする。「その他」「関連」のような、中身を言わない名前は避ける。
4. 定義は、「含む」「含まない」を1文ずつ書く。「含まない」には、隣り合うグループとの境目を書く。

失敗しやすい点は、キーワードの語をつなぐだけの名前をつけることだ。語は表層の特徴であり、グループの意味とは限らない。

## 2. 軸の確認

全グループの名前を並べ、同じ問いへの答えになっているかを確かめる。

- 例: 「予算」「人員」「スケジュール」は、「何が制約か」への答えで、軸がそろっている。
- 例: 「予算」「営業部」「来月」が並んでいたら、「何が」「誰が」「いつ」が混ざっている。軸が混在している。

軸が混ざっているときは、次の順に進める。

1. 混ざっている軸を挙げる。
2. 目的に合う軸を1つ選ぶ。候補は2つまでにして、利用者に示す。
3. 選んだ軸で、グループを組み直す。必要なら `--k` を変えて再実行する。

軸が混ざっている分割は、項目が複数のグループに入りうるので、排他性を満たせない。

## 3. 排他性の判定

`boundary_pairs` の上位3組までを見る。`count` が0なら、この判断は省略してよい。

組ごとに、境界の項目を読み、次のどれかに分類する。

| 分類 | 見分け方 | 対応 |
|---|---|---|
| 定義の問題 | 項目の大半を、一方に寄せるルールを書ける | 定義の「含まない」にルールを足す。項目を移す |
| 2つの軸の交差 | 項目が、両方のグループの性質を同時に持つ | 軸を分けて、2段の分類にする。または、主たる軸を決める |
| 切り方の問題 | 2つのグループの境目が曖昧で、ルールも書けない | 統合する。または、`--k` を変えて再実行する |

どの分類にも、境界の項目の原文を添える。

境界の項目が、組をまたいで散らばっているときは、特定の組の問題ではない。軸の混在(判断2)か、k の不適合を疑う。

## 4. 網羅性の穴の指摘

網羅性は、データだけでは判定できない。何を全体とみなすかは、目的で決まるためである。目的から、全体を先に定める。

1. 目的から期待される観点を、自分で列挙する。外部の知識を使うときは、その旨を書く。
2. 観点ごとに、入っているグループを探す。見つからなければ、穴の候補とする。
3. どのグループにも収まらず、「その他」に入りそうな項目を探す。多いときは、軸の見直しを疑う。
4. 穴の候補には、「データにない」ことと、「目的から期待される」ことの、両方の根拠を書く。

穴の候補は、推測である。「入力に存在しない」ことは、「世の中に存在しない」ことを意味しない。報告では、推測と明記する。

## 設計の根拠

この設計は、次の資料に基づく。

- 埋め込み → クラスタリング → ラベルづけという流れ: [BERTopic](https://arxiv.org/abs/2203.05794)
- クラスタが利用者の目的で変わること、目的を言葉で与えて説明つきのクラスタにすること: [Goal-Driven Explainable Clustering via Language Descriptions](https://arxiv.org/abs/2305.13749)
- LLM を、小さな埋め込みモデルの案内役にすること: [ClusterLLM](https://arxiv.org/abs/2305.14871)
- LLM によるトピックと概念の抽出: [LLooM](https://arxiv.org/abs/2404.12259)、[TopicGPT](https://arxiv.org/abs/2311.01449)
- 分類体系の生成と評価: [TnT-LLM](https://arxiv.org/abs/2403.12173)
- 埋め込みモデル: [ruri-v3-310m](https://huggingface.co/cl-nagoya/ruri-v3-310m)(クラスタリングには `トピック: ` の接頭辞)、[multilingual-e5-base](https://huggingface.co/intfloat/multilingual-e5-base)(`query: ` の接頭辞が必須)
- silhouette: Rousseeuw (1987), Silhouettes: a graphical aid to the interpretation and validation of cluster analysis

元になったプログラムは、[MECE_Refineder](https://github.com/Mr-Kondo/MECE_Refineder) である。
